## Feature: 실시간 필기 동기화

선생님의 필기가 학생 화면에 실시간으로 반영되어야 한다.

### Scenario: 선생님이 펜으로 필기하면 학생 화면에 실시간 표시

```gherkin
Given 선생님과 학생이 동일 세션에 접속해 있다
  And 선생님이 "pen" 도구를 선택한 상태이다
When 선생님이 캔버스 위에 스트로크를 그린다
Then 학생 화면에 100ms 이내에 진행 중인 스트로크가 표시된다
  And 선생님이 손을 떼면 학생 화면의 스트로크가 완성된 Stroke로 교체된다
```

### Scenario: 스트로크 완료 시 Reliable 채널로 전체 데이터 전송

```gherkin
Given 선생님과 학생이 동일 세션에 접속해 있다
When 선생님이 하나의 스트로크를 완성한다
Then Reliable Data Channel("stroke_complete")로 전체 Stroke protobuf가 전송된다
  And 학생 측에서 Lossy 스트리밍 미리보기가 완성된 스트로크로 교체된다
  And 스트로크의 모든 포인트(x, y, pressure, timestamp)가 보존된다
```

### Scenario: 포인트 스트리밍 중 일부 패킷 유실

```gherkin
Given 선생님과 학생이 동일 세션에 접속해 있다
  And 네트워크 패킷 손실률이 10%인 환경이다
When 선생님이 캔버스 위에 스트로크를 그린다
Then 학생 화면에 일부 중간 포인트가 누락된 스트로크 미리보기가 표시된다
  And 선생님이 손을 떼면 Reliable 채널로 수신된 완전한 스트로크로 교체된다
  And 최종 렌더링은 선생님 화면과 동일하다
```

### Scenario: 다양한 도구로 필기 동기화

```gherkin
Given 선생님과 학생이 동일 세션에 접속해 있다
When 선생님이 다음 도구를 순서대로 사용한다:
  | 도구    |
  | pen     |
  | pencil  |
  | marker  |
  | eraser  |
  | shape   |
Then 각 도구의 스트로크가 학생 화면에 올바른 스타일로 표시된다
  And eraser로 지운 영역은 학생 화면에서도 지워진다
```

### Scenario: Undo/Redo 동기화

```gherkin
Given 선생님이 3개의 스트로크를 그린 상태이다
  And 학생 화면에 3개의 스트로크가 표시되어 있다
When 선생님이 Undo를 수행한다
Then 학생 화면에서 마지막 스트로크가 제거된다
When 선생님이 Redo를 수행한다
Then 학생 화면에 해당 스트로크가 다시 표시된다
```

## Feature: 음성 통화

수업 중 선생님과 학생이 양방향 음성으로 소통할 수 있어야 한다.

### Scenario: 세션 접속 시 음성 통화 자동 연결

```gherkin
Given 선생님이 세션을 생성했다
When 학생이 해당 세션에 참가한다
Then 양방향 음성 통화가 자동으로 시작된다
  And 선생님의 음성이 학생에게 150ms 이내에 전달된다
  And 학생의 음성이 선생님에게 150ms 이내에 전달된다
```

### Scenario: 마이크 음소거 및 해제

```gherkin
Given 선생님과 학생이 음성 통화 중이다
When 학생이 마이크 음소거 버튼을 누른다
Then 선생님에게 학생의 음성이 전달되지 않는다
  And 학생 UI에 음소거 상태가 표시된다
When 학생이 마이크 음소거를 해제한다
Then 선생님에게 학생의 음성이 다시 전달된다
```

### Scenario: 음성 통화와 필기 동시 동작

```gherkin
Given 선생님과 학생이 음성 통화 중이다
When 선생님이 음성으로 설명하면서 동시에 필기한다
Then 학생에게 음성과 필기가 동시에 전달된다
  And 필기 동기화 지연이 100ms를 초과하지 않는다
  And 음성 품질이 저하되지 않는다
```

### Scenario: 음성만 끊겼을 때 필기 동기화 유지

```gherkin
Given 선생님과 학생이 세션에 접속해 있다
  And 음성 통화와 필기 동기화가 모두 동작 중이다
When 음성 연결만 일시적으로 끊긴다
Then 필기 동기화는 정상적으로 계속된다
  And 음성 재연결이 자동으로 시도된다
  And "음성 연결 중..." 상태가 UI에 표시된다
```

## Feature: 뷰포트 동기화

선생님의 캔버스 확대/축소/이동이 학생에게 실시간 반영되어야 한다.

### Scenario: 선생님이 캔버스를 확대하면 학생도 확대

```gherkin
Given 선생님과 학생이 동일 세션에 접속해 있다
  And 초기 뷰포트 scale이 1.0이다
When 선생님이 pinch-to-zoom으로 scale을 2.0으로 확대한다
Then 학생 화면의 scale이 200ms 이내에 2.0으로 변경된다
  And 선생님이 확대한 중심점이 학생 화면의 중심에 위치한다
```

### Scenario: 선생님이 캔버스를 이동하면 학생도 이동

```gherkin
Given 선생님과 학생이 동일 세션에 접속해 있다
When 선생님이 캔버스를 pan하여 center를 (500, 300)으로 이동한다
Then 학생 화면의 center가 200ms 이내에 (500, 300)으로 변경된다
  And 선생님이 보는 영역과 학생이 보는 영역의 중심이 일치한다
```

### Scenario: 서로 다른 화면 비율의 디바이스에서 뷰포트 적응

```gherkin
Given 선생님은 iPad (4:3 비율)을 사용한다
  And 학생은 Galaxy S24 (19.5:9 비율)을 사용한다
When 선생님이 특정 영역을 확대하여 수업한다
Then 학생 화면에서 선생님이 가리킨 영역이 화면 중심에 위치한다
  And 선생님의 scale이 유지되되 학생 디바이스 비율에 맞게 여백이 조정된다
  And 필기 내용이 잘리지 않는다
```

### Scenario: 빠른 연속 뷰포트 변경 시 throttle 적용

```gherkin
Given 선생님과 학생이 동일 세션에 접속해 있다
When 선생님이 500ms 동안 연속적으로 캔버스를 pan한다
Then 뷰포트 이벤트가 100ms 간격으로 throttle되어 최대 5회 전송된다
  And 학생 화면은 부드럽게 전환된다
  And 최종 뷰포트 상태는 선생님과 일치한다
```

### Scenario: 페이지 전환 시 뷰포트 초기화

```gherkin
Given 선생님이 페이지 1에서 scale 2.0, center (500, 300)으로 수업 중이다
When 선생님이 페이지 2로 전환한다
Then 학생 화면도 페이지 2로 전환된다
  And 페이지 2의 뷰포트는 기본값(scale 1.0, center 0,0)으로 설정된다
When 선생님이 다시 페이지 1로 돌아온다
Then 페이지 1의 뷰포트가 이전 상태(scale 2.0, center 500,300)로 복원된다
```

## Feature: 세션 관리

선생님이 수업 세션을 생성하고 학생이 참가하여 수업을 진행한다.

### Scenario: 선생님이 세션을 생성한다

```gherkin
Given 선생님이 앱에 로그인한 상태이다
When 선생님이 "수업 시작" 버튼을 누른다
Then 고유한 세션 ID가 생성된다
  And 학생 초대용 참가 코드가 발급된다
  And LiveKit Room이 생성된다
  And 선생님이 세션에 자동 접속된다
```

### Scenario: 학생이 참가 코드로 세션에 참가한다

```gherkin
Given 선생님이 세션을 생성하고 대기 중이다
  And 참가 코드 "ABC123"이 발급되었다
When 학생이 참가 코드 "ABC123"을 입력한다
Then 학생이 해당 세션에 접속된다
  And 선생님에게 "학생이 입장했습니다" 알림이 표시된다
  And 음성 통화가 자동 시작된다
  And 학생은 read-only 모드로 캔버스를 볼 수 있다
```

### Scenario: 잘못된 참가 코드 입력

```gherkin
Given 활성 세션이 존재하지 않는 참가 코드 "WRONG1"이 있다
When 학생이 참가 코드 "WRONG1"을 입력한다
Then "유효하지 않은 참가 코드입니다" 오류 메시지가 표시된다
  And 세션에 접속되지 않는다
```

### Scenario: 선생님이 수업을 종료한다

```gherkin
Given 선생님과 학생이 세션에서 수업 중이다
  And 선생님이 3개 페이지에 걸쳐 필기했다
When 선생님이 "수업 종료" 버튼을 누른다
Then 선생님에게 "수업을 종료하시겠습니까?" 확인 다이얼로그가 표시된다
When 선생님이 확인한다
Then .obt 타임라인 파일이 자동 생성된다
  And 학생에게 "수업이 종료되었습니다" 알림이 표시된다
  And 양측의 LiveKit 연결이 정리된다
  And 학생에게 "리플레이 보기" 버튼이 제공된다
```

### Scenario: 이미 2명이 접속한 세션에 추가 접속 시도

```gherkin
Given 선생님과 학생이 이미 세션에 접속해 있다
When 다른 사용자가 같은 참가 코드로 접속을 시도한다
Then "세션이 가득 찼습니다 (최대 2명)" 오류 메시지가 표시된다
  And 접속이 거부된다
```

## Feature: 세션 리플레이

수업 종료 후 학생이 리플레이로 수업을 다시 볼 수 있어야 한다.

### Scenario: 수업 종료 후 리플레이 재생

```gherkin
Given 1시간 분량의 수업 세션이 정상 종료되었다
  And .obt 타임라인 파일이 생성되었다
When 학생이 "리플레이 보기"를 선택한다
Then 리플레이가 2초 이내에 로딩된다
  And 수업 시작 시점부터 필기가 60fps로 재현된다
  And 선생님이 사용한 모든 도구의 스트로크가 올바르게 표시된다
```

### Scenario: 리플레이에서 특정 시점으로 seek

```gherkin
Given 리플레이가 재생 중이다
  And 전체 수업 시간이 60분이다
When 학생이 타임라인 바에서 30분 지점을 탭한다
Then 30분 시점의 캔버스 상태가 즉시 표시된다
  And 해당 시점부터 재생이 계속된다
  And 모든 페이지의 스트로크 상태가 30분 시점에 맞게 복원된다
```

### Scenario: 리플레이 재생 속도 조절

```gherkin
Given 리플레이가 1x 속도로 재생 중이다
When 학생이 재생 속도를 2x로 변경한다
Then 필기 애니메이션이 2배 빠르게 재생된다
  And 페이지 전환도 2배 빠르게 진행된다
When 학생이 재생 속도를 0.5x로 변경한다
Then 필기 애니메이션이 0.5배 느리게 재생된다
```

### Scenario: 리플레이 시 뷰포트 재현

```gherkin
Given 수업 중 선생님이 특정 영역을 scale 3.0으로 확대하여 설명했다
  And 해당 ViewportChangedEvent가 타임라인에 기록되었다
When 리플레이가 해당 시점에 도달한다
Then 뷰포트가 선생님이 보던 scale 3.0, 동일 center로 재현된다
  And 학생 디바이스 비율에 맞게 적응 렌더링이 적용된다
```

### Scenario: 다른 디바이스에서 리플레이 재생

```gherkin
Given 수업이 선생님의 iPad (4:3)에서 진행되었다
  And .obt 파일이 저장되었다
When 학생이 iPhone (19.5:9)에서 리플레이를 재생한다
Then 선생님의 center 좌표 기준으로 화면이 재구성된다
  And 필기 내용이 잘리지 않고 표시된다
  And 선생님이 강조한 영역이 학생 화면 중심에 위치한다
```

## Feature: 늦은 참가자 동기화

학생이 수업 중간에 참가해도 현재 상태를 즉시 볼 수 있어야 한다.

### Scenario: 수업 시작 10분 후 학생이 참가

```gherkin
Given 선생님이 10분 전에 세션을 시작했다
  And 페이지 1에 5개의 스트로크, 페이지 2에 3개의 스트로크를 그렸다
  And 현재 페이지 2를 보고 있다
When 학생이 참가 코드로 세션에 접속한다
Then 학생에게 페이지 2의 현재 캔버스 스냅샷이 3초 이내에 전송된다
  And 학생 화면에 페이지 2의 3개 스트로크가 표시된다
  And 선생님의 현재 뷰포트(scale, center)가 적용된다
  And 이후 실시간 필기 동기화가 시작된다
```

### Scenario: 스냅샷 전송 중 새 스트로크 발생

```gherkin
Given 학생이 세션에 접속하여 스냅샷을 수신 중이다
When 스냅샷 전송이 완료되기 전에 선생님이 새 스트로크를 그린다
Then 새 스트로크 이벤트는 큐에 저장된다
  And 스냅샷 수신이 완료된 후 큐의 이벤트가 순차 적용된다
  And 최종 상태가 선생님 화면과 동일하다
```

### Scenario: 늦은 참가 시 페이지 목록 동기화

```gherkin
Given 선생님이 3개의 페이지를 추가하고 수업 중이다
When 학생이 늦게 참가한다
Then 학생에게 3개 페이지의 목록과 ID가 전달된다
  And 현재 활성 페이지로 자동 이동된다
  And 페이지 전환 시 해당 페이지의 스냅샷이 지연 로딩된다
```

### Scenario: 대량 필기 상태의 늦은 참가

```gherkin
Given 선생님이 30분간 수업하여 10개 페이지에 총 200개 스트로크를 그렸다
When 학생이 세션에 접속한다
Then 현재 활성 페이지의 스냅샷이 우선 전송된다 (3초 이내)
  And 나머지 페이지는 백그라운드에서 점진적으로 동기화된다
  And 동기화 진행률이 UI에 표시된다
```

## Feature: 네트워크 끊김 및 재접속

불안정한 네트워크 환경에서도 수업이 지속되어야 한다.

### Scenario: 30초 이내 일시적 네트워크 끊김

```gherkin
Given 선생님과 학생이 수업 중이다
When 선생님의 네트워크가 15초간 끊긴다
Then 선생님은 로컬에서 필기를 계속할 수 있다
  And 학생 화면에 "선생님 연결 중..." 상태가 표시된다
  And 15초 후 네트워크가 복구되면 자동으로 재접속된다
  And 끊긴 동안의 이벤트가 순차적으로 학생에게 전달된다
  And 양측 캔버스 상태가 일치한다
```

### Scenario: 30초 초과 네트워크 끊김

```gherkin
Given 선생님과 학생이 수업 중이다
When 학생의 네트워크가 45초간 끊긴다
Then 학생 화면에 "연결이 끊겼습니다" 알림이 표시된다
  And "재접속" 버튼이 제공된다
  And 선생님은 수업을 계속할 수 있다
When 학생이 "재접속" 버튼을 누른다
Then 세션에 재접속된다
  And 현재 캔버스 상태가 풀 싱크로 동기화된다
  And 실시간 동기화가 재개된다
```

### Scenario: 재접속 시 이벤트 큐 flush

```gherkin
Given 선생님의 네트워크가 10초간 끊긴 상태이다
  And 선생님이 끊긴 동안 5개의 스트로크를 그렸다
When 네트워크가 복구되어 자동 재접속된다
Then 로컬에 큐잉된 5개의 StrokeAddedEvent가 순차 전송된다
  And 학생 화면에 5개의 스트로크가 빠르게 표시된다
  And 이벤트의 원래 타임스탬프가 보존된다
```

### Scenario: 학생 네트워크 끊김 동안 선생님 수업 지속

```gherkin
Given 선생님과 학생이 수업 중이다
When 학생의 네트워크가 끊긴다
Then 선생님에게 "학생 연결 끊김" 알림이 표시된다
  And 선생님은 필기와 수업을 계속할 수 있다
  And 타임라인 기록은 중단되지 않는다
When 학생이 재접속한다
Then 끊긴 동안의 모든 변경사항이 동기화된다
```

### Scenario: 양측 모두 재접속 후 상태 불일치 감지

```gherkin
Given 선생님과 학생 모두 일시적으로 연결이 끊겼다가 재접속했다
When 양측의 캔버스 상태에 불일치가 감지된다
Then 선생님 측 상태를 기준(source of truth)으로 학생에게 풀 싱크가 전송된다
  And 학생 캔버스가 선생님 상태로 덮어씌워진다
  And "상태가 동기화되었습니다" 알림이 표시된다
```

## Feature: 다중 페이지 관리

선생님이 여러 페이지를 추가/전환/삭제하며 수업할 수 있어야 한다.

### Scenario: 수업 중 새 페이지 추가

```gherkin
Given 선생님이 페이지 1에서 수업 중이다
When 선생님이 "페이지 추가" 버튼을 누른다
Then 새 빈 페이지가 추가된다
  And 학생 화면에도 새 페이지가 추가된다
  And PageAddedEvent가 타임라인에 기록된다
```

### Scenario: 페이지 전환 동기화

```gherkin
Given 선생님이 3개 페이지를 만들고 페이지 2에서 수업 중이다
When 선생님이 페이지 3으로 전환한다
Then 학생 화면도 자동으로 페이지 3으로 전환된다
  And PageChangedEvent가 타임라인에 기록된다
  And 페이지 3의 캔버스 내용이 올바르게 표시된다
```

### Scenario: 페이지 삭제 동기화

```gherkin
Given 선생님이 3개 페이지를 만들고 페이지 2에서 수업 중이다
When 선생님이 현재 페이지(페이지 2)를 삭제한다
Then 학생 화면에서도 페이지 2가 삭제된다
  And 양측 모두 페이지 1 또는 3으로 자동 이동된다
  And PageRemovedEvent가 타임라인에 기록된다
```

### Scenario: 페이지 전체 지우기 동기화

```gherkin
Given 선생님이 페이지 1에 10개의 스트로크를 그린 상태이다
When 선생님이 "전체 지우기"를 수행한다
Then 학생 화면에서도 페이지 1의 모든 스트로크가 제거된다
  And PageClearedEvent가 타임라인에 기록된다
  And 빈 캔버스가 표시된다
```

## Feature: 디바이스 전환 (Edge Case)

수업 중 또는 리플레이 중 다른 디바이스로 전환하는 상황을 처리한다.

### Scenario: 학생이 수업 중 디바이스를 전환

```gherkin
Given 학생이 iPad에서 수업에 참가 중이다
When 학생이 iPad에서 나가고 iPhone으로 같은 세션에 재접속한다
Then 기존 iPad 연결이 종료된다
  And iPhone에서 현재 캔버스 상태가 풀 싱크로 동기화된다
  And iPhone 화면 비율에 맞게 뷰포트가 적응된다
  And 실시간 동기화가 재개된다
```

### Scenario: 선생님이 수업 중 앱이 백그라운드로 전환

```gherkin
Given 선생님과 학생이 수업 중이다
When 선생님의 앱이 백그라운드로 전환된다
Then LiveKit 연결이 유지된다 (최대 30초)
  And 학생에게 "선생님 일시 정지" 상태가 표시된다
When 선생님의 앱이 포그라운드로 복귀한다
Then 수업이 즉시 재개된다
  And 추가 동기화 없이 이전 상태가 유지된다
```

### Scenario: 리플레이 중 앱 종료 후 재시작

```gherkin
Given 학생이 리플레이를 30분 지점에서 재생 중이다
When 학생이 앱을 강제 종료한다
  And 앱을 다시 실행한다
Then 리플레이 목록에서 해당 수업을 다시 선택할 수 있다
  And 리플레이가 처음부터 시작된다
```

## Feature: 세션 상태 관리 (Edge Case)

비정상적인 세션 종료 및 상태 처리를 다룬다.

### Scenario: 선생님이 종료하지 않고 앱을 닫았을 때

```gherkin
Given 선생님과 학생이 수업 중이다
When 선생님이 "수업 종료"를 누르지 않고 앱을 닫는다
Then 학생에게 "선생님이 나갔습니다" 알림이 표시된다
  And 학생은 세션에서 30초간 대기한다
When 30초 이내에 선생님이 재접속하지 않는다
Then 세션이 자동 종료된다
  And 현재까지의 타임라인으로 .obt 파일이 생성된다
  And 학생에게 "리플레이 보기" 옵션이 제공된다
```

### Scenario: 학생이 수업 중 퇴장

```gherkin
Given 선생님과 학생이 수업 중이다
When 학생이 세션에서 나간다
Then 선생님에게 "학생이 나갔습니다" 알림이 표시된다
  And 선생님은 수업을 계속하거나 종료할 수 있다
  And 타임라인 기록은 계속된다
When 학생이 같은 참가 코드로 재입장한다
Then 현재 상태가 풀 싱크로 동기화된다
```

### Scenario: 세션 타임아웃

```gherkin
Given 세션이 생성된 후 120분이 경과했다
When 세션 시간이 120분에 도달한다
Then 양측에 "수업 시간이 종료됩니다 (5분 전)" 알림이 표시된다
When 5분 추가 경과 후 125분에 도달한다
Then 세션이 자동 종료된다
  And .obt 파일이 자동 생성된다
```

### Scenario: 동시에 같은 계정으로 두 디바이스 접속

```gherkin
Given 학생이 iPad에서 세션에 참가 중이다
When 같은 학생 계정으로 iPhone에서 같은 세션에 접속을 시도한다
Then iPad의 기존 연결이 종료된다
  And iPhone에서 세션에 접속된다
  And iPad에 "다른 기기에서 접속되었습니다" 알림이 표시된다
```
