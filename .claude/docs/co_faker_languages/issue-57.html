제외 (후속)

  • 힌디어(en_IN 은 영어 유지) · 번체 중국어(zh-Hant · zh_TW · zh_HK · zh_MO — 간체를 주지 않는다, co_demo_prefs 정책과 동일)

5. 설계 결정

5.1 언어 설정 해석 (S1 · #58)

  • CoFakerLanguages.resolve(tag) 는 대소문자 · -/_ · 스크립트 · .인코딩 · @modifier 를 무시하고 언어와 지역을 뽑는다. faker.language 는 정규화된 언어 코드(ja_jp → ja).
  • CoFaker.forLanguage(tag) 는 언어를 그 언어의 국가 로케일로 만든다: ko→ko · en→en_us · zh→zh_cn · ja→ja_jp · de→de_de · fr→fr_fr · ru→ru_ru · it→it_it · pt→pt_br. 앱의 "언어 설정"에는 이 진입점을 쓴다 — 언어 코드만 넘기는 CoFaker(locale: 'ja') 는 #55 의 풍부한 국가 데이터가 아니라 0.10.0 의 얇은 언어 데이터를 받기 때문이다.
  • 기존 CoFaker(locale: …) 의 기본 모듈 출력은 바이트 동일 — 0.10.0 스냅샷 회귀가 수정 없이 통과해야 한다. 번체 코드는 resolve/forLanguage 에서만 거부하고(영어 폴백), 기존 zh_TW 출력은 유지한다.

5.2 도메인 저작 데이터의 언어 키 이관 (S2 · #59)

  • 조회 순서: faker.language → en. ko 는 ko. 지원 밖 언어와 커스텀 로케일은 영어(기존 영어 폴백 회귀 유지).
  • 번들은 언어별 파일(lib/src/l10n/{lang}/…)이다. ko · en 은 기존 문구를 옮기고, 나머지 7개 언어는 빈 스텁을 레지스트리에 미리 등록한다 — 언어 Story 7건이 병렬로 진행돼도 서로 같은 줄을 고치지 않는다.
  • 도메인 지원 여부(domain)는 번들 레지스트리에서 계산한다. 수동 플래그가 없어야 언어 Story 가 레지스트리 · 테스트를 건드리지 않는다.
  • 커스텀 로케일이 도메인 문구를 주입하는 확장 지점이 있어 es · ar · hi 같은 후속 언어를 코드 변경 없이 추가할 수 있다.
  • 안전망: 이관 전에 ko · en 의 도메인 출력 전수 덤프를 픽스처로 고정하고 이관 후에도 바이트 동일을 증명한다(CoFakerDomains.all 의 모든 role × seed 3종 × 레코드 인덱스, 전용 생성기 공개 메서드).

5.3 clinic · saas 의 금액 · 서식 · 문구를 데이터 필드로 (S3 · #60)

  • 금액 규모 계수 · 반올림 단위 · 할부 기준 · 포인트 단위 · 통화 서식 · 인라인 문구(회/x · 님 · 휴일 · 상태 메시지 · saas.dart:935~1148)를 CoFakerClinicData · CoFakerClinicOps · CoFakerClinicTexts · CoFakerSaasData · CoFakerSaasOps 의 필드로 옮긴다.
  • 영어 데이터 = 현재 영어 동작(USD · $), 한국어 데이터 = 현재 한국어 동작(KRW) 을 필드 값으로 표현한다. 데이터가 없는 언어는 영어 데이터로 폴백하므로 기존 모든 로케일 코드의 출력이 바뀌지 않는다(0.10.0 스냅샷 수정 없이 통과).
  • 새 언어 데이터는 한국 전용 값(faker.korea.* — 카드 승인번호 · 현금영수증 · 도로명 주소)을 쓰지 않는다. 영어의 기존 출력은 바이트 동일 보존을 위해 데이터 플래그로 유지한다.
  • 새 언어 데이터는 영어 데이터(범용 피부과 · 미용 클리닉 픽스처)의 구조를 따른다. 한국 전용(NHIS · KCD · 주민번호)은 가져오지 않는다. 코드값(CONS01 · nhis · waiting)은 로케일 독립이다.

5.4 커버리지 게이트 (S4 · #61)

  • 언어 L 의 모든 팩 role · 전용 생성기 · clinic · saas 문구를 생성해 검사한다: (a) 한글 누출 0 (L≠ko) (b) ja · zh · ru 는 해당 문자 체계 포함 (c) 영어 목록과 항목별 동일 비율이 임계 이하(차용어 · 고유명사는 허용 목록) (d) 목록 길이가 영어와 같음 (e) 미등록 키 보고.
  • 안전 스캔: authored_data_safety_test 의 ['ko', 'en'] 고정을 지원 언어 전체로 — 가상 표기((가상)/(fictional))의 언어별 규약과 브랜드 거부 목록의 언어별 표기. 새 언어 데이터는 자동으로 검사 대상이 된다.
  • 0.10.0 스냅샷은 기본 모듈 키는 모든 stable 코드에서 계속 바이트 동일, 도메인 키(clinic.* · schema.patient · schema.invoice)는 도메인 현지화가 아직 없는 언어에만 적용한다. 현지화 여부는 레지스트리에서 읽는다.
  • 언어별 문서 틀 docs/languages/{lang}.md(용어집 · 검토 체크리스트) — 언어 Story 는 자기 파일만 고친다.

8. 리스크와 완화

리스크완화
7개 언어 도메인 용어 번역의 품질 · 일관성 — 번역은 AI 초안이며 원어민 검수가 없다언어별 용어집(docs/languages/{lang}.md)과 일관성 검사, 커버리지 게이트(S4), 원어민 검토 체크리스트. 원어민 검수는 머지 게이트가 아니라 권장 사항이고 PR 설명에 명시한다. 품질 문제는 후속 fix 로 받는다.
하위호환 — #55 가 "기존 로케일 출력은 0.10.0 과 바이트 동일"을 약속했다기본 모듈 출력은 스냅샷으로 고정. 도메인 출력은 해당 언어 Story 머지 때에만 바뀌고, 스냅샷 범위를 레지스트리 기반으로 분리하며, CHANGELOG 에 의도된 동작 변경으로 기록한다. S3 은 데이터가 없는 언어의 출력을 바꾸지 않는다.
규모 · 병합 충돌 — 약 11,000 문자열, 한 Epic PR언어별 파일 분리 + 레지스트리 스텁 사전 등록 + 문서 파일도 언어별. 각 Story 는 자기 파일만 수정. 중간 PR 은 로컬 게이트(format · analyze · test)로 검증하고 최종 Epic PR 에서 CI.
